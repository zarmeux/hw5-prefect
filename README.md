# ДЗ №5 — Prefect, Apache Spark и YARN

Продолжаем работу с кластером из прошлых ДЗ. Поток Prefect запускает Spark
в YARN, читает ранее загруженные события из HDFS, выполняет трансформации и
сохраняет дневную сводку как внешнюю таблицу Hive `hw5.events_daily`.

В репозитории есть инструкция, скрипты автоматизированной установки и запуска,
проверки результата и GitHub Actions для проверки исходного кода.

**Статус:** полный запуск на кластере подтверждён 20 ноября 2026 года.
Все четыре задачи Prefect завершились успешно; Spark-приложение
`application_1795070226999_0001` выполнилось в YARN, результат прочитан из Hive
и сверен с исходными данными. Отчёт находится в
[evidence/RESULTS.md](evidence/RESULTS.md).

## Быстрый запуск

На управляющей машине с работающими HDFS, YARN и Hive из ДЗ №1–4, из корня
скачанного или клонированного репозитория:

```bash
sudo apt-get update
sudo apt-get install -y python3-venv curl
sudo bash scripts/install.sh
sudo bash scripts/run.sh
```

Установщик использует Spark 3.5.7 и создаёт отдельное окружение с Prefect 3.6.4.
FastAPI закреплён на версии 0.119.1 для совместимости с этим Prefect.
Поток запускается без аккаунта Prefect Cloud. Подробности установки, перенос
архива на edge, требования и устранение ошибок — в [INSTALL.md](INSTALL.md).

## Что происходит

Поток `hw5-events-daily` в [flows/events_flow.py](flows/events_flow.py)
последовательно проверяет кластер, запускает Spark-обработку, регистрирует
таблицу и сверяет результат. При ошибке последующие задачи не выполняются.

| Пункт задания | Реализация |
|---|---|
| Сессия Spark под управлением YARN | `spark-submit --master yarn --deploy-mode client`, проверка master в коде |
| Подключение HDFS | `/etc/hadoop-yarn`, адрес из `core-site.xml`, проверка HDFS URI |
| Чтение ранее загруженных данных | CSV из `hw3/events`, дата из каталога партиции |
| Трансформации | Приведение типов, нормализация, проверка строк, удаление дублей, агрегация по дням |
| Сохранение как таблицы | Parquet в HDFS и внешняя таблица `hw5.events_daily` в существующем Hive |

Сессия, чтение и обработка выполняются в одном Spark-приложении внутри задачи
Prefect. Драйвер работает на edge, исполнители — в контейнерах YARN.
Как в ДЗ №4, таблица регистрируется через Beeline: это позволяет использовать
существующий Hive 4 Metastore вместе со Spark 3.5.7.

## Данные и ожидаемый результат

Источник: `/user/hive/warehouse-external/hw3/events`.
Результат: `/user/hive/warehouse-external/hw5/events_daily`.
В каждом CSV три поля без заголовка: `event_id,user_id,event_type`.
Дата берётся из каталога `event_date=YYYY-MM-DD`.

Для пяти событий из ДЗ №3 ожидается:

| event_date | events_count | unique_users | page_views | signups | purchases | purchase_share |
|---|---:|---:|---:|---:|---:|---:|
| 2026-10-20 | 3 | 2 | 1 | 1 | 1 | 0.333333 |
| 2026-10-21 | 2 | 2 | 1 | 1 | 0 | 0.0 |

Это ожидаемые значения для исходного примера. Проверка сравнивает Hive с
фактическими результатами Spark для текущего содержимого HDFS.
`purchase_share` — доля событий покупки среди всех событий дня.

## Повторный запуск и проверка

```bash
sudo bash scripts/run.sh
```

Результат пересчитывается полностью, без накопления дублей. Источник и результат
ДЗ №4 сохраняются. Локальная блокировка исключает одновременные запуски этой
работы на одной машине; кэширование задач Prefect отключено.
Перезапись Parquet не транзакционная: во время пересчёта таблицу не следует
читать или изменять другой программой.

Поток проверяет успешное завершение приложения YARN, наличие исполнителей и
успешных задач Spark, а затем сравнивает каждую строку и показатель в Hive и Spark.
Журналы сохраняются в `evidence/<run_id>/`. После успешного выполнения
автоматически обновляется [evidence/RESULTS.md](evidence/RESULTS.md).

GitHub Actions проверяет Python, импорт потока с установленным Prefect,
синтаксис Bash и тесты. CI не подключается к учебному кластеру.
